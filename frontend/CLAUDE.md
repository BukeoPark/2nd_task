# frontend/ — React + 카카오맵 대시보드 규칙

루트 `CLAUDE.md`의 전역 규칙 위에 다음을 더한다.

## 스택
- React + Vite + TypeScript. 패키지 매니저는 npm.
- 지도: 카카오맵 JS SDK. 앱 키는 `import.meta.env.VITE_KAKAO_JS_APP_KEY`로 주입하고 코드에 하드코딩하지 않는다(카카오 콘솔에 도메인 등록 필요).
- 서버 상태: React Query. 클라이언트 전역 상태가 필요하면 zustand(가볍게).

## 구조
- `src/features/<기능>/` 단위로 컴포넌트·훅·API 호출을 함께 둔다.
  - `features/map`: 카카오맵 바탕(`KakaoMap`)·행정동 경계·R-ONE 임대료 마커
  - `features/food`: 요식업·카페 지도 — 확대 단계별 버블(구·행정동·상권·매장 점), 업종·지표 필터, 범례, 스타벅스·다이소 표시,
    위치 검색(`SearchBox`)과 이용 순서 안내(`FlowGuide`: 검색 → 위치 선택 → 업종 선택 → 후보 지역 비교), 입지 비교(`ComparePanel`), 매장 목록 '더 보기'(`UnitStoreList`)
    - 지도 위에 얹는 표시(스타벅스·다이소 마커, 임대료)는 오른쪽 `MapLayerToolbar` 에서 켜고 끈다. 상단바(`FoodTopBar`)에는 검색·업종·지표 선택만 둔다.
    - **인구 히트맵**(`features/food/HeatmapLayer`, 계산은 `lib/heatmap`, 자료는 `GET /api/food/heat`): 지도 레이어 도구의 '인구 히트맵'에서 끔 / 유동인구 / 인구밀도(상주인구÷면적) / 직장인구 밀도를 고른다.
      상권 단위 점(중심점 + 값)을 캔버스에 번지게 쌓아 파랑→초록→노랑→빨강으로 칠한다(도로·건물 단위 분포가 아님). 색의 세기는 상위 5% 값을 1 로 둔 비율이고, 값이 없는 상권은 0 이 아니라 표시하지 않는다.
      범례·분기·출처·한계는 '?' 말풍선에 둔다. 캔버스는 마우스를 통과시키고 지도 이동·확대마다 다시 그린다(버블보다 아래).
    - 지도 오른쪽 아래 독(`MapDock`)은 범례와 순위표(`RankingTable`, 정렬은 `lib/ranking`) 탭이고 탭을 한 번 더 누르면 접힌다(좁은 화면은 접힌 채 시작).
      순위표는 지도 버블을 마우스로 눌러야만 열리던 요약을 키보드·스크린리더로도 열게 하는 같은 정보의 표 경로다 — 지도에 새 지표를 더하면 표에도 같은 값·업종 범위·'자료 없음' 사유가 나와야 한다.
    - 범례에서 앵커 브랜드는 지도 마커와 같은 글자 든 네모(`Mark`), 증감 색은 둥근 점(`Dot`)으로 모양을 달리한다(빨강이 다이소와 '상승'에 같이 쓰이므로 색만으로 구분하지 않는다).
    - **매장 점은 업종 이모티콘**(`lib/storeGlyph`): 서울시 외식 10개 업종마다 모양을 달리해(한식 🍚·중식 🍜·일식 🍣·양식 🍝·제과 🥐·패스트푸드 🍔·치킨 🍗·분식 🍢·호프 🍺·커피 ☕, 대응 없는 세부 업종은 🍽️) 같은 색 점이라 업종이 헷갈리던 문제를 줄인다.
      모양은 `GET /api/food/stores` 가 주는 `svc`(서울시 업종 코드)로 정하고, 범례(`FoodLegend`)에 업종별 모양을 보인다. 새 업종 모양을 바꿀 때는 `SVC_GLYPHS` 한 곳만 고친다(10개가 서로 달라야 하며 테스트가 지킨다). 이모티콘이 읽히도록 점 크기(`pointStyle`)를 22px 안팎으로 둔다.
    - 매장 점 강조: 상세를 연 매장은 `SelectedStoreMarker`(큰 링 + 이름표, 어느 확대 단계에서도), 같은 비교 단위·같은 서울시 업종 매장은 파란 링(`peer`), 그 외는 흐리게(`other`)로 그린다.
      역할·모양은 `lib/pointStyle`, 비교 단위 경계는 `UnitBoundaryLayer`, 강조할 매장 id·경계는 `GET /api/stores/{id}/peer-stores`(내 매출 비교와 같은 단위·업종 규칙)에서 받는다.
      색에만 기대지 않도록 크기·링·투명도로도 구분하고, 가려지거나 화면 밖이면 `lib/reveal` 로 지도를 옮긴다(잘 보이면 옮기지 않는다). 점 스타일 변경은 점을 다시 만들지 않고 갱신한다.
    - '내 매출 비교'의 '비교 기준' 박스(`lib/compareBasis`)가 비교 단위·이유·비교 업종·강조되는 매장 수를 말한다. 지도 단위가 요약 기준과 달라지면 패널 맨 위에 안내한다.
    - 행정동·상권 종합분석(`features/area/AreaOverviewPanel`)도 같은 레일(`components/TabRail`)을 쓴다: 첫 항목 '요약'(기준 안내·지도 버튼·핵심 카드 3개)을 포함해 성장성·안정·경쟁·소비 수요·입지·(행정동만)세부 상권·매장 목록을 한 번에 하나씩 본다(고정 영역이 길어 내용이 아래로 밀리던 문제를 피한다). 항목마다 맨 위에 상권 이름·유형이 나오고, 항목마다 다른 색(`AREA_TAB_STYLE`)을 레일 선택 표시와 내용 제목(`components/RailHeading`)에 똑같이 쓴다. 매장 상세 묶음도 `SCOPE_STYLE` 색을 레일·제목·범위 라벨에 같이 쓴다. 글자색은 배경과 대비 4.5:1 이상(테스트가 지킨다).
      항목 구성은 `lib/areaTabs`, 레일 id 는 `railIds` 의 prefix(`area-`)로 매장 상세와 구분한다. 선택하지 않은 항목도 그려 두고 `hidden` 으로만 가린다. 항목 안의 지표·문구는 그대로 둔다.
    - 상권 인사이트 리포트(`features/stores/report`): 매장 상세의 '상권 인사이트 리포트 뽑기' 버튼이 전체 화면 위에 4쪽짜리 리포트(요약 / 매출 수준·흐름 / 시간대·연령 / 경쟁·폐업·입지 요인)를 펼치고 인쇄(PDF 저장)할 수 있다.
      자료는 매장 상세가 이미 쓰는 조회(동네 매출 비교·반경 인허가·입지 영향력)를 같은 쿼리 키로 재사용하고, 숫자·문장은 `lib/insightReport` 순수 함수가 규칙으로 만든다(자료가 없는 쪽은 만들지 않는다).
      원인을 단정하지 않고 '관측'과 '가능한 해석'만 쓰며 리뷰·평점은 쓰지 않는다. 인쇄해도 같게 보이도록 앱 테마와 무관한 고정 색(`reportColors`)을 쓴다.
    - **이용 모드**(`lib/mode`, `features/guide/useMode`): 자영업자 / 예비 창업자. 주소 `?mode=` > 이 브라우저에 기억한 값 > 기본(자영업자). 상단바 `ModeSwitch` 로 바꾸고, 모드에 따라 이용 순서 안내(`lib/flow`)·검색창 안내문이 달라지며
      예비 창업자에게는 매장 상세의 '내 가게' 묶음을 보이지 않는다. 랜딩의 모드 버튼은 이 `?mode=` 를 붙여 `/map` 으로 보낸다.
    - **이용 순서 표시**(`FlowGuide`, `lib/flow`): 모드별 단계(자영업자 6단계·예비 창업자 4단계)와 지금 단계·다음 행동. 단계는 화면에서 일어난 일(`ProgressKey`, `useProgress`)로만 끝난 것으로 본다.
      처음 열어 둔 기본 행정동은 사용자가 한 일로 세지 않는다. 앞 단계를 건너뛰어도 막지 않는다. 좁은 화면은 지금 단계 하나만 보인다.
    - **출처·기준일은 숨겨 둔다**: `SourceNote`·지표 행·범례의 출처는 항상 펼치지 않고 `components/InfoTip`('?' 에 마우스를 올리면, 휴대폰은 누르면 말풍선)에 담는다. '출처'라는 글자는 쓰지 않고 '?' 를 해당 데이터 이름(`label`)이나 값 글줄 바로 옆에 둔다. 업종 범위·주의 문구는 숫자 가까이에 그대로 둔다.
    - **랜딩·지도 한 주소**: 5173 하나로 랜딩('/')과 지도·보고서('/map?mode=owner|founder')를 모두 낸다(`lib/route` 가 경로를 풀고 `App` 이 고른다 — 라우터 라이브러리 없음). 랜딩은 `features/landing/`(`LandingPage`·`content`·`landing.css` 는 `.lp` 안에 가둔 스타일)이며 `landing/`(Next.js)의 구성·문구를 옮긴 것이다. 랜딩 버튼은 새로고침 없이 `/map?mode=` 로 간다.
      예전 주소('/?mode=…'·공유 링크 '/?mode=&unit=&svc=')는 `resolveRoute` 가 같은 검색값 그대로 `/map` 으로 바꿔(replaceState, 기록 칸 안 늘림) 열고, 모르는 경로는 '/' 로 보낸다. 운영 호스팅은 모든 경로를 `index.html` 로 돌려줘야 한다(SPA 대체 응답). 개발 서버는 기본으로 해 준다.
    - **용어는 `lib/terms` 한 곳**: 비교 단위는 '상권'(밖이면 행정동), '동네'·'점포수'·'점포당 월평균 매출' 같은 표기는 쓰지 않는다(`tests/terms.test.ts` 가 막는다).
    - **튜토리얼**(`features/guide/TourLayer`·`useTour`, 단계 정의는 `lib/tour`): 처음 방문하면(모드별로) 환영 팝업 → '튜토리얼 시작'이면 대상 요소만 밝게 하고 말풍선을 붙인다. 막지 않는다(밝은 곳은 그대로 눌러 볼 수 있고, 다음·이전·건너뛰기·방향키·Esc).
      '다시 보지 않기'·끝까지 봄·건너뜀은 `tour:v1:<모드>` 로 기억하고, 상단 '도움말'로 언제든 다시 본다. 대상이 지금 화면에 없으면(매장 상세·입지 비교 등) 가운데 카드가 `fallback` 문구로 말한다. 말풍선 자리는 `placeTip`(화면 안으로 눌러 넣음), 좁은 화면은 아래 시트.
      단계를 더하거나 고칠 때는 `lib/tour` 의 TOURS 만 고치고, 가리킬 요소에 `data-tour` 를 붙인다.
    - **해석상 유의사항은 탭마다 한 곳에 모은다**(`components/NoteHost`·`Caveat`): 각 탭(매장 상세 묶음·종합분석 항목)은 위쪽에 접힌 '읽는 법·유의사항 (N)' 하나를 두고, 안의 `<Caveat>` 문장은 제자리에 그리지 않고 거기로 모인다.
      **제자리에 남기는 것**: 값이 0 이거나 자료가 없는 이유·조회 실패 같은 상태 안내(`Notice`), 숫자 바로 옆의 핵심 경고(예: 이 값은 이 매장의 실제 매출이 아님, 미래 폐업 확률이 아님, 상관이지 인과가 아님), 업종 범위. 새 문구를 쓸 때 설명·배경 문장은 `Caveat`, 핵심 경고는 눈에 보이게 쓴다.
    - **좁은 화면(≤720px, `useNarrow`)**: 상단바는 한 줄이 넘치면 바 안에서 옆으로 밀어 보게 하고(페이지가 옆으로 넓어지지 않게) 제목·검색창을 줄인다. 서랍(매장 상세·상권 분석)은 화면 폭을 꽉 채우고 지도 확대·축소 단추보다 위에 두며,
      서랍이 열려 있는 동안에는 지도 도구·이용 순서·범례를 가린다(패널을 덮지 않게). 레일은 패널 위 가로 탭(옆으로 밀기)이고 튜토리얼 카드는 아래 시트다. 실제 폭 확인은 iframe 을 390px 로 둔 하니스에서 한다(브라우저 창 에뮬레이션은 폭을 반영하지 않는다).
    - **종합분석 항목 구성**: 요약(지표 카드 → 지도 버튼 → '읽는 법·유의사항' → 안내 → 리포트 버튼 순) / 유형(참고용 분류·판정 근거·강점·주의사항) / 특성(교통·배후 수요·상업·경쟁 네 영역) / 성장성 / 안정·경쟁 / 소비 수요 / 입지 / 세부 상권 / 매장 목록.
      특성은 네 영역 카드에 값·근거를 보인다(핵심 메시지·색 제목은 복잡해져 뺐다). 좋고 나쁨·성공 가능성은 말하지 않는다.
    - **종합분석 요약의 3단**(`features/area/AreaBriefCard`, 계산은 `lib/areaBrief`): ① 확인된 사실(모드별 2~3개) ② 어떻게 읽을까?(증감 부호·개폐업률 크기만, 점포 10곳 미만이면 '분석 보류') ③ 다음 확인사항(눌러서 이동). 매장 상세 '이 매장'(자영업자)에도 같은 3단(`StoreBriefCard`, `lib/storeBrief`).
      예비 창업자는 레일에 '비용 점검'(`CostCheckSection`, `lib/costCheck` — 입력 기반 시뮬레이션, 저장 키 `founderCostCheck:v1`, '내 가게' 기록과 분리)·'현장 확인'(`VisitChecklistSection`, `lib/visitChecklist`)이 더해진다.
      관심 지역(`lib/favorites`, 최대 10곳)·최근 본 지역(`lib/recentUnits`)은 이 브라우저(localStorage)에만 두고, 공유 주소(`?unit=level:code&svc=`)에는 모드·지역·업종 코드만 담는다(내 매출·비용 없음). 비교 상단의 '차이가 큰 지표'는 `lib/compareHighlights`(유리한 곳을 고르거나 점수로 합치지 않음).
      요약 해석은 리포트와 같은 규칙을 쓴다(`lib/interpretRules`: 기준값의 1.25배 이상일 때만 '눈에 띄게 높다', 증감은 부호대로, 표본 점포는 서울시 집계 최근 분기 → 상가정보). 임계값이 `areaLens`·`areaReport` 원문과 어긋나지 않는지 `tests/interpretRules.test.ts` 가 지킨다. 근거가 부족하면 해석 없이 숫자만 보인다.
      **지역 비교 화면**(`features/food/CompareDashboard`): 화면 너비를 넓게 쓰고(최대 1760px), 맨 위에 '지역별 핵심 지표' 표(열 = 담은 지역)와 '눈여겨볼 차이 3가지'(`lib/compareHighlights` — 모든 지역의 값·차이를 센 방식·기간·업종 범위를 함께 보임)를 놓는다. 매출·경쟁·수요·안정성·임대료(참고) 상세 차트와 전체 표는 그 아래다. 종합점수·우수 지역 선정은 없다.
      **창업 비용 점검**은 지도 옆 좁은 패널이 아니라 작업 화면(`CostCheckModal`, 포털)에서 한다 — 입력(왼쪽)·결과(오른쪽)를 나란히(좁은 화면은 위아래), 입력은 바로 결과에 반영된다. 패널 탭(`CostCheckLauncher`)에는 저장된 값의 결과 한 줄과 작업 화면 단추만 있다. 계산은 그대로 `lib/costCheck`→`lib/breakeven`.

      선택하지 않은 묶음도 그려 두고 `hidden` 으로만 가려 반경 선택·Google 불러오기 같은 상태를 유지한다. 좁은 화면(`useNarrow`)에서는 레일 대신 패널 위 가로 탭이고, 매장이 바뀌면 묶음 선택·입력을 처음으로 되돌린다.
    - 입지 영향력(`LocationInfluenceSection.tsx`): 반경(250m·500m·1km) 앵커·경쟁 점포는 `LocationRadiusSection`(주변), 상권 수요 유형(업무·혼합·주거형)·입지 요인과 점포당 추정매출의 관계는 `LocationAreaSection`(상권)이다. 문장은 `lib/locationText` 순수 함수로 만들고
      '상관이지 인과 아님·매장 매출 예측 아님'을 항상 보이는 곳에 둔다. 95% 구간이 0 을 포함하면 방향을 단정하지 않고, 서버가 `useful=false` 로 알리면 '참고용' 안내를 띄운다.
    - 행정동·상권 종합분석의 '유형·특성' 항목(`features/area/AreaCharacterSection`, 서버 `area_character`)은 그 단위 **경계 기준**의 교통·배후 수요·앵커/상업·경쟁 4개 영역과 참고용 규칙 분류(복수 특성: 업무·주거·교통 거점·상업 집중, 혼합형, 판정 보류)를 보인다.
      종합점수·창업 성공 확률은 없고, 매장 반경 값(주변)과 섞지 않는다. 유형 판정은 외식 전체 기준이고 경쟁 영역만 선택 업종을 따른다. 매장 상세 '상권' 묶음에는 유형 한 줄(`AreaCharacterLine`)과 이동 링크만 둔다. 문장·색은 `lib/areaCharacter`.
    - 주변의 교통 블록(③ 접근성·④ 이용 수요)은 지하철과 버스를 함께 보인다(`lib/railText` 문장·지도 표시 계획, 서버 `rail_access`). 역 수는 환승 노선을 겹쳐 세지 않는 역사 단위이고, **거리는 공식 역 중심점까지의 직선거리이며 출입구 거리라고 쓰지 않는다**(출입구 좌표는 카카오 로컬 결과라 이용 조건 미확인으로 서버가 `entrance_data.enabled=false` 로 내려 사용하지 않는다 — 출입구 체크박스·문구는 숨기고, 공식 출입구 자료가 생기면 켠다).
      이용량은 연결된 역만의 2025 하루 평균 승차·하차(관측된 부분 합계, 없으면 '자료 없음', 0 아님)이고 지하철과 버스를 더하지 않는다. 지도에는 같은 반경 결과의 역 중심점 마커(`RailStationLayer`)를 그리며 `StoreDetailPanel` 이 메뉴·반경·매장 변경 때 함께 지운다.
    - 주변의 ② 주요 집객시설(`FacilityBlock`, `lib/facilityText`, 서버 `facility_access`)은 의료/상업(백화점·대형마트·쇼핑몰·아울렛)/문화·여가(영화관·문화시설)/교육으로 묶어 종류별 개수·가장 가까운 시설·직선거리를 보인다.
      공식 자료·이용 권한 확인 시설만 오고(카카오 로컬 장소 데이터는 응답에도 지도에도 없다), 공식 원천이 없는 종류는 '자료 없음'(0곳 아님), 좌표 누락·범위 불완전은 '확인 불가'·'N곳 이상'으로 0곳과 구분한다. 방문객·매출·점수로 바꾸지 않는다.
      지도 마커(`FacilityLayer`)는 기본 꺼짐 체크박스로만 켜고, 반경·매장·메뉴가 바뀌면 `StoreDetailPanel` 이 함께 지운다. 긴 설명·출처·기준일은 ⑥ 분석 기준 Fold 에 모은다.
    상권 통계(매출 추이·인구·시간대)는 `features/area` 에만 둔다(매장 상세에 반복하지 않는다).
    - 모든 블록은 제목 옆 **범위 라벨**(`ScopeTag`, `Section scope=`)로 이 정보의 범위를 말한다: 이 매장 / 반경 N m / 소속 상권 / 내 입력. 네 범위는 `lib/scope` 가 정의하고 레일 메뉴(이 매장·주변·상권·내 가게)와 같은 값이다(`lib/panelGroups` 테스트가 둘이 어긋나지 않게 지킨다).
      새 블록을 더할 때는 범위를 먼저 정하고, 같은 값(예: 스타벅스·다이소 거리, 같은 소분류 수)을 다른 블록에 다시 적지 않는다.
    - 내 가게 점검(`MyStoreCheckupSection`): 월 매출 기록을 동네 같은 업종의 **변화율**과 견주고(금액 수준은 카드 추정과 달라 비교하지 않는다), 비용을 넣어 손익분기를 본다.
      기록은 `lib/myStoreStorage`(localStorage, 가게별)에만 두고 서버로 보내지 않는다. 판단은 `lib/checkup`·`lib/breakeven` 순수 함수.
      **내 매출 입력은 '내 가게 점검'에서만 받는다.** 상세 패널이 `useMyStoreRecord` 로 기록을 한 번만 들고, 내 매출 비교(읽기 전용)·상권 운영 점검·프랜차이즈 참고는
      `lib/checkup.latestMonth` 로 구한 가장 최근 기록 월의 값을 읽는다. 새 블록에 매출 입력칸을 따로 만들지 않는다.
- `src/components/`는 기능 독립적인 공용 UI 만.
- `src/lib/`는 apiClient(백엔드 `/api` 베이스), 지도 헬퍼, 포맷터.
- 페이지 조립은 `src/pages/`.

## 규약
- 백엔드 호출은 `src/lib/apiClient` 를 통해서만. 컴포넌트에서 `fetch` 직접 호출 금지.
- 지도 레이어(버블 등)는 별도 컴포넌트로 분리하고, 데이터→시각 속성(크기·색) 매핑 함수는 `lib/`에 순수 함수로 둔다.
- 색상·구간 기준은 상수 모듈 한 곳에서 관리(범례와 지도가 같은 값을 쓴다).
- 좌표는 `{ lon, lat }` 객체로 다루고, 카카오 SDK 가 요구하는 `(lat, lng)` 변환은 헬퍼에서만 한다.
- Google 고객평가는 `<gmp-place-details>`(Places UI Kit)로만 표시한다. 내용을 읽어 저장·재가공·점수화하지 않고, 테두리로 우리 콘텐츠와 구분한다.
- 값 0 / 정보 없음 / 해당 없음 / 조회 실패 / 연동 준비 중을 서로 다른 문구로 구분한다(`components/Notice`). 정보가 부족한 매장도 기본정보는 보여준다.
- 각 정보에는 출처·기준일(`SourceNote`)을 붙인다.
- API 키·개인정보를 URL 쿼리스트링에 넣지 않는다.
- 조회 화면은 최초 로딩 / 조건 변경 후 재조회 / 정상 0곳 / 자료 없음 / 조회 실패를 구분한다(`lib/queryState`). 새 조건의 결과를 기다리며 이전 결과를
  남겨 두면(`keepPreviousData`) 흐리게 표시하고 클릭·비교·상세 진행을 막으며, 실패에는 '다시 시도'를 둔다.
- 그 값이 적용된 업종 범위('커피-음료 전체 기준')는 화면(항목 제목 아래 한 줄)에서 항상 보이게 하고, 지표마다의 범위는 이름 옆 '?' 말풍선에도 둔다. 원천에 없는 세부 업종 값은 추정·배분하지 않는다.

## 테스트
- `npm test` (= `node --test tests/*.test.ts`) — 새 의존성 없이 Node 의 타입 제거 실행으로 돈다. 그래서 검증할 판단 로직(`lib/queryState`·`flow`·`searchTarget`·`foodText`)은
  다른 모듈을 import 하지 않는 순수 함수로 두고, 테스트는 `tests/` 에 `.ts` 확장자로 import 한다(`erasableSyntaxOnly` 범위의 문법만 사용).
- 빌드 확인: `npm run build` (= `tsc -b && vite build`), 린트: `npm run lint`.
